I researched the three integrations and checked the practical limits that matter for your anime-story pipeline. The biggest constraint is Qwen video length: Wan text-to-video supports up to 15 seconds for text-only generation, while reference-to-video is 2–15 seconds with images only and 2–10 seconds when a reference video is included; voice-timbre reference audio is limited to 1–10 seconds, and total reference media is capped at 5 items. [docs.qwencloud](https://docs.qwencloud.com/api-reference/video-generation/wan27-reference-to-video/create-task)

## Backblaze + Genblaze

Genblaze is built for media pipelines, not just storage, and it automatically handles execution, retries, storage, and a provenance record for each run that you can persist in Backblaze B2. The Backblaze docs also describe B2 as the place to store outputs and manifests, and the GitHub repo notes that every run can produce a canonical provenance manifest you can embed into media files and persist to B2. [github](https://github.com/backblaze-labs/genblaze)

What that means for your app:
- Store generated episode clips, thumbnails, character refs, subtitles, and manifests in B2.
- Use Genblaze to orchestrate provider calls and keep the workflow auditable.
- Use B2 as the durable source of truth for episode assets and metadata. [backblaze](https://www.backblaze.com/docs/cloud-storage-genblaze-developer-guide)

## Qwen video limits

For your specific concern about consistency and voice:
- Wan 2.7 reference-to-video supports character portrayal from reference image/video, and reference videos can also replicate voice timbre. [docs.qwencloud](https://docs.qwencloud.com/api-reference/video-generation/wan27-reference-to-video/create-task)
- The model supports multi-panel storyboard prompts, so you can describe scenes like “Scene 1 [0-3s]” and “Scene 2 [3-6s]” in one request. [docs.qwencloud](https://docs.qwencloud.com/api-reference/video-generation/wan27-reference-to-video/create-task)
- Audio can be automatic dubbing or custom audio; the docs say automatic dubbing is generated by default when you do not pass an audio URL. [docs.qwencloud](https://docs.qwencloud.com/api-reference/video-generation/wan27-reference-to-video/create-task)
- The output video URL expires after 24 hours, so your pipeline should download and save results to B2 immediately. [docs.qwencloud](https://docs.qwencloud.com/api-reference/video-generation/wan27-reference-to-video/create-task)

For your anime use case, the practical takeaway is that full episodes should be built as stitched clips rather than one long generation call. The docs also say the output is billed per successfully generated second, which reinforces a clip-based pipeline. [docs.qwencloud](https://docs.qwencloud.com/api-reference/video-generation/wan27-reference-to-video/create-task)

## Consistency strategy

The Qwen docs give you two useful consistency tools: reference images/videos for character likeness and multi-shot prompts for continuity across shots. Wan 2.7 also supports up to 5 reference assets total, so you can keep a small “character bible” per main cast member. [docs.qwencloud](https://docs.qwencloud.com/api-reference/video-generation/wan27-reference-to-video/create-task)

For a stronger consistency layer, your architecture should:
- Store each character’s reference set in B2.
- Store episode state and character embeddings in CockroachDB.
- Feed both the current scene context and the character references into Wan for every clip. [cockroachlabs](https://www.cockroachlabs.com/docs/dev/vector-indexes)

## CockroachDB memory layer

CockroachDB supports vector indexing for ANN search over embedding data, and its docs also describe combining vector data with relational and JSON data. That makes it a good fit for persistent story memory: character profiles, scene state, prior episode summaries, and retrieval of the closest matching character or scene context. [cockroachlabs](https://www.cockroachlabs.com/docs/stable/vector)

For your hackathon angle, the most relevant tools are:
- Distributed vector indexing for character/story memory retrieval. [cockroachlabs](https://www.cockroachlabs.com/docs/dev/vector-indexes)
- MCP Server for connecting agent tooling directly to CockroachDB. [cockroachdb-ai.devpost](https://cockroachdb-ai.devpost.com)
- ccloud CLI for database and cloud automation. [youtube](https://www.youtube.com/watch?v=KUYDdwiH6ec)
- Agent Skills for reusable database/operator workflows. [cockroachlabs](https://www.cockroachlabs.com/blog/cockroachdb-ai-agents-agent-ready-database/)

## Practical MVP limits

A realistic first version should target:
- 3–10 second clips per scene, especially if you use reference video. [docs.qwencloud](https://docs.qwencloud.com/api-reference/video-generation/wan27-reference-to-video/create-task)
- 1–3 reference images per character, plus an optional voice reference audio under 10 seconds. [docs.qwencloud](https://docs.qwencloud.com/api-reference/video-generation/wan27-reference-to-video/create-task)
- Automatic dubbing only if you want quick voice output; custom voice reference if character voice continuity matters. [docs.qwencloud](https://docs.qwencloud.com/api-reference/video-generation/wan27-reference-to-video/create-task)
- Immediate persistence of every output to B2 because generation URLs expire after 24 hours. [docs.qwencloud](https://docs.qwencloud.com/api-reference/video-generation/wan27-reference-to-video/create-task)

## Recommended build shape

For “StoryForge Anime,” the safest production-minded pipeline is:
1. Write episode/scene plan with the agent.
2. Retrieve character memory from CockroachDB.
3. Generate short scene clips in Wan using reference images/videos plus optional voice reference.
4. Save every clip, subtitle file, manifest, and thumbnail to B2 through Genblaze.
5. Stitch clips into an episode and archive the final deliverable in B2. [github](https://github.com/backblaze-labs/genblaze)

The main hidden constraint is not just duration; it’s asset management and consistency. The docs show Wan is best used as a clip generator with explicit references, while Genblaze and B2 give you the durable storage and provenance layer you need to make the app feel production-ready. [backblaze](https://www.backblaze.com/docs/cloud-storage-genblaze-developer-guide)
